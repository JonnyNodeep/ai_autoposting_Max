# MAX API — ключевые моменты для интеграции

> Источник: https://dev.max.ru/docs-api
> Все эндпоинты используют домен: `https://platform-api2.max.ru`

---

## 1. Общие сведения

- **Протокол:** HTTPS REST, JSON
- **Авторизация:** заголовок `Authorization: <access_token>` (передача через query-параметры не поддерживается)
- **Rate limit:** 30 rps
- **HTTP коды:** 200 (OK), 400, 401, 404, 405, 429 (rate limit), 503

### Получение токена бота

Токен выдаётся при создании бота на [business.max.ru](https://business.max.ru/self):
Чат-боты → Перейти → Расширенные настройки → Настроить

### Webhook vs Long Polling

| | Webhook | Long Polling |
|---|---|---|
| **Production** | ✅ | ❌ |
| **Dev/Test** | ✅ | ✅ |
| **Требования** | HTTPS, порт 443, доверенный сертификат (включая сертификаты Минцифры) | — |
| **Метод** | `POST /subscriptions` | `GET /updates` |

## 2. Ключевые эндпоинты для проекта

### Бот

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/me` | Информация о боте (user_id, name, username, is_bot) |
| PATCH | `/me/commands` | Установка команд бота |

### Каналы (chats)

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/chats/{chatId}` | Информация о канале/чате |
| PATCH | `/chats/{chatId}` | Редактирование канала (title, icon, description) ***требуются права админа*** |
| GET | `/chats/{chatId}/members/me` | Проверка членства бота в канале |
| GET | `/chats/{chatId}/members/admins` | Список администраторов |
| GET | `/chats/{chatId}/pin` | Закреплённое сообщение |
| PUT | `/chats/{chatId}/pin` | Закрепить сообщение |
| DELETE | `/chats/{chatId}/pin` | Открепить сообщение |

> ⚠️ `GET /chats` (список всех чатов) — **DEPRECATED с июня 2026**. Вместо него использовать `POST /subscriptions`.

### Сообщения

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/messages` | Получение сообщений (по `chat_id` или `message_ids`) |
| GET | `/messages/{messageId}` | Получение одного сообщения |
| POST | `/messages` | Отправка сообщения/поста |
| PUT | `/messages` | Редактирование сообщения |
| DELETE | `/messages` | Удаление сообщения |
| POST | `/answers` | Ответ на callback (нажатие inline-кнопки) |

### Медиа

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/uploads?type=` | Получение URL и токена для загрузки медиа |

### Подписки (Webhook)

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/subscriptions` | Создание webhook-подписки |
| GET | `/subscriptions` | Список активных подписок |
| DELETE | `/subscriptions` | Отписка от webhook |

## 3. Отправка сообщения (`POST /messages`)

### Параметры запроса

| Параметр | Тип | Описание |
|----------|-----|----------|
| `chat_id` | int64 (query) | ID канала/чата для отправки |
| `user_id` | int64 (query) | ID пользователя для отправки в личку |

### Тело запроса (NewMessageBody)

```json
{
  "text": "Текст поста (до 4000 символов)",
  "attachments": [
    {
      "type": "image",
      "payload": {
        "token": "...",
        "url": "https://..."
      }
    },
    {
      "type": "inline_keyboard",
      "payload": {
        "buttons": [
          [
            {"type": "callback", "text": "Кнопка 1", "payload": "action_1"},
            {"type": "callback", "text": "Кнопка 2", "payload": "action_2"}
          ]
        ]
      }
    }
  ],
  "format": "markdown",
  "notify": true,
  "disable_link_preview": false,
  "link": null
}
```

### Форматирование текста

| Стиль | Markdown | HTML |
|-------|----------|------|
| *курсив* | `*text*` или `_text_` | `<i>` или `<em>` |
| **жирный** | `**text**` или `__text__` | `<b>` или `<strong>` |
| ~~зачёркнутый~~ | `~~text~~` | `<del>` или `<s>` |
| ++подчёркнутый++ | `++text++` | `<ins>` или `<u>` |
| `моноширинный` | `` `code` `` | `<pre>` или `<code>` |
| [ссылка](url) | `[text](url)` | `<a href="url">text</a>` |
| ^^выделенный^^ | `^^text^^` | `<mark>text</mark>` |
| # заголовок | `# text` | `<h1>`-`<h4>` |
| > цитата | `> text` | `<blockquote>text</blockquote>` |
| @упоминание | `[Имя Фамилия](max://user/user_id)` | `<a href="max://user/user_id">Имя Фамилия</a>` |

## 4. Работа с вложениями (attachment)

### Типы вложений

| Тип | Форматы | Макс. размер |
|-----|---------|-------------|
| `image` | JPG, JPEG, PNG, GIF, TIFF, BMP, HEIC | 50 МБ, 7680×7680 px |
| `video` | MP4, MOV, MKV, WEBM | 250 МБ |
| `audio` | MP3, WAV, M4A и др. | 256 МБ, до 60 мин |
| `file` | TXT, DOC, PDF и др. | 4 ГБ |
| `inline_keyboard` | — | 210 кнопок, 30 рядов, до 7 в ряду |
| `location` | — | — |

### Комбинации вложений (до 12 total)

- Видео + изображения + 1 inline_keyboard (любые пропорции в пределах 12)
- Только видео: до 12
- Только изображения: до 12
- Файл + inline_keyboard (только вместе, не с видео/изображениями)

### Загрузка изображений (процесс из 3 шагов)

1. **Запрос URL для загрузки:**
```
POST /uploads?type=image
Authorization: <token>
→ { "url": "https://iu.oneme.ru/upload.do?...", "token": "..." }
```

2. **Загрузка файла:**
```
POST <url из шага 1>
Content-Type: multipart/form-data
data=@image.png
→ { "token": "_3Rarh13n..." }
```

3. **Отправка сообщения с вложением:**
```json
{
  "text": "Пост с картинкой",
  "attachments": [
    {"type": "image", "payload": {"token": "_3Rarh13n..."}}
  ]
}
```

### Альтернатива для изображений

Изображения можно отправлять по прямой ссылке (`url`) без предзагрузки:
```json
{"type": "image", "payload": {"url": "https://example.com/image.jpg"}}
```

> ⚠️ После загрузки медиа может потребоваться пауза перед отправкой — файл обрабатывается на сервере. При ошибке `attachment.not.ready` — повторить с увеличивающейся задержкой.

## 5. Получение сообщений (`GET /messages`)

### Параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `chat_id` | int64 | ID канала (обязателен, если нет `message_ids`) |
| `message_ids` | string | ID сообщений через запятую |
| `from` | int64 | Unix timestamp — сообщения до этого времени |
| `to` | int64 | Unix timestamp — сообщения начиная с этого времени |
| `count` | 1-100 | Количество сообщений (по умолчанию 50) |

Сообщения возвращаются в обратном порядке (последние первыми).

## 6. Типы событий (Update)

Webhook присылает объект `Update` со следующими `update_type`:

| Событие | Описание | Важно для проекта |
|---------|----------|-------------------|
| `bot_added` | Бот добавлен в канал | ✅ Регистрация канала |
| `bot_started` | Пользователь начал общение с ботом | ✅ Инициация пользователя |
| `bot_stopped` | Пользователь остановил бота | Отписка |
| `bot_removed` | Бот удалён из канала | ✅ Удаление канала |
| `message_created` | Новое сообщение/пост в канале | ✅ Анализ стиля |
| `message_edited` | Сообщение отредактировано | |
| `message_removed` | Сообщение удалено | |
| `message_callback` | Нажатие inline-кнопки | ✅ Обработка «Опубликовать/Переделать» |
| `user_added` | Пользователь добавлен в канал | |
| `user_removed` | Пользователь удалён из канала | |
| `chat_title_changed` | Название канала изменено | |
| `dialog_cleared` | История диалога очищена | |
| `dialog_removed` | Диалог удалён | |

### Структура Update

```json
{
  "update_type": "message_created",
  "timestamp": 1234567890,
  "chat_id": 123,
  "user": { ... },
  "message": { ... },
  "is_channel": true
}
```

## 8. Inline-клавиатура (кнопки)

Типы кнопок:

| Тип | Действие |
|-----|----------|
| `callback` | Отправка `message_callback` боту (без текста в чат) |
| `link` | Открытие ссылки в новой вкладке |
| `message` | Отправка текстового сообщения боту |
| `request_contact` | Запрос контакта пользователя |
| `request_geo_location` | Запрос геолокации |
| `open_app` | Открытие мини-приложения |
| `clipboard` | Копирование текста в буфер обмена |

Ограничения:
- До 210 кнопок в 30 рядов, до 7 в ряду
- Для `link`/`open_app`/`request_geo_location`/`request_contact` — до 3 в ряду
- Ссылка для `link` — до 2048 символов

## 9. Webhook: требования и retry-политика

- **URL:** только HTTPS, порт 443 (не указывается в URL)
- **Сертификат:** доверенный ЦС или сертификат Минцифры (самоподписанные не поддерживаются)
- **Ответ:** HTTP 200 в течение 30 секунд
- **Секрет:** `secret` → заголовок `X-Max-Bot-Api-Secret` в каждом запросе (опционально, но рекомендуется)

### Retry-политика

До 10 повторных попыток с экспоненциальной задержкой:
- 1-я: 60 сек
- 2-я: 150 сек (60 × 2.5)
- 3-я: 375 сек (150 × 2.5)
- ...

Если за 8 часов нет успешного ответа — бот автоматически отписывается от webhook.

## 10. Выводы для архитектуры проекта

1. **Публикация:** бот должен быть администратором канала. Пост через `POST /messages` с `chat_id`, текст до 4000 знаков, Markdown-форматирование.

2. **Изображения:** AI генерирует картинку → сохраняем локально → загружаем через `POST /uploads?type=image` → используем токен в `POST /messages`. Альтернативно — отдаём прямой URL (если хостим изображения).

3. **Inline-кнопки:** для всех действий пользователя (Опубликовать, Переделать, Сделать короче...) используем `callback`-кнопки. Обработка нажатий через webhook → `POST /answers`.

4. **Webhook:** основной способ получения событий. Для production — только webhook. Aiogram должен получать webhook-запросы, а не использовать long polling.

5. **Анализ стиля:** `GET /messages?chat_id=<channel_id>&count=100` для получения последних постов канала.

6. **Редактирование канала:** `PATCH /chats/{chatId}` — установка логотипа, названия, описания (бот должен быть админом).

7. **Aiogram совместимость:** MAX API структурно близок к Telegram Bot API — aiogram можно использовать с кастомным HTTP-клиентом, направляя запросы на `platform-api2.max.ru` вместо Telegram API.
